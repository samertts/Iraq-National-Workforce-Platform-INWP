# إعداد نموذج طلب الوصول عبر Formspree

النموذج في `site/console/access.html` هو قناة لاستقبال طلب تواصل ومراجعته يدويًا، وليس خدمة إنشاء حساب. لا يُمنح أي دور ولا يُنشأ حساب عند وصول الرسالة. يجب أن يتحقق مسؤول مخول من الهوية والجهة والحاجة ثم يتبع مسار provisioning مؤسسي منفصل.

## الحالة الافتراضية

التكامل معطل عمدًا في `site/console/access-config.js`: قيمة `endpoint` فارغة و`enabled` تساوي `false`. بذلك تبقى الحقول وزر الإرسال معطلين. لا تغيّر هذه القيم حتى ينشئ مالك المنصة نموذجًا في حساب Formspree، ويتحقق من بريد الاستلام، ويوافق صراحةً على إرسال بيانات الطلب إلى ذلك المزود.

معرّف Formspree الظاهر ضمن عنوان النموذج ليس مفتاحًا سريًا؛ سيظهر ضمن ملفات الموقع العامة. لا تضع أي API key أو رمز مصادقة في هذا الملف أو في مستودع عام.

## إعداد المزود

1. ينشئ مالك المنصة حسابًا ونموذجًا مخصصًا في Formspree، ويتحقق من البريد المستهدف ويحدد من يراجِع الطلبات. تجنب توصيل النموذج تلقائيًا بأوراق عمل أو CRM عام قبل تقييم صلاحيات الوصول والاحتفاظ.
2. يضبط تقييد النطاق في لوحة Formspree على أصل الموقع `samertts.github.io`، ويفعل وسائل تصفية الرسائل المزعجة المتاحة. يحتوي النموذج على مصيدة `_gotcha`، لكنها ليست ضمانًا ضد كل الرسائل الآلية.
3. يراجع إشعار الخصوصية وموافقة مقدم الطلب، وإعدادات تخزين/حذف البيانات وتوجيه الرسائل في حساب المزود. يرسل النموذج الاسم الوظيفي والبريد المؤسسي والجهة/الوحدة والسبب الاختياري القصير، إضافة إلى خانة موافقة ومصيدة spam.
4. بعد موافقة المالك الصريحة، يوضع endpoint بالشكل `https://formspree.io/f/FORM_ID` في `endpoint`، وتحوّل `enabled` إلى `true`. تقبل الواجهة فقط HTTPS وعلى المضيف `formspree.io` ومسار `/f/<id>`، وتظل وسائل الاتصال من JavaScript مغلقة. لا تغيّر ذلك إلى مزود أو نطاق آخر دون مراجعة CSP.
5. يختبر المالك النموذج ببيانات اختبارية غير شخصية، ويتأكد أن طلبًا واحدًا يصل إلى الوجهة الصحيحة وأن الطلب المرفوض أو الفاشل لا يوحي بنجاح زائف. بعد ذلك ينشر الموقع عبر GitHub Pages ويتحقق من الرابط المباشر.

الحقول لا تطلب رقمًا وطنيًا أو كلمة مرور أو وثائق أو بيانات حساسة. الإرسال عبر مزود خارجي ينقل البيانات إليه؛ يجب ألا يُفعّل قبل إشعار المتقدم بوضوح وموافقته. لا تستخدم القناة لعمليات تشغيلية حساسة أو قرارات موارد بشرية، ولا تعتبرها نظام تذاكر موثوقًا أو سجل تدقيق. لا تضمن الواجهة وحدها عدم التكرار أو السرية التامة أو زمن التسليم؛ فهذه خصائص تتطلب خدمة خادمية وحوكمة مستقلة.

## الاختبارات والحدود

اختبارات الموقع تفرض بقاء endpoint فارغًا والتكامل معطلًا في المستودع، ولا تختبر إرسالًا حقيقيًا. لا يُرسل اختبار CI بيانات إلى Formspree. إرسال POST أصلي يتطلب فتح المتصفح إلى نتيجة Formspree أو سلوك النجاح المعد في لوحة المزود، وقد يعتمد على حصة الحساب وإعداداته. يفضل تفعيل تقييد النطاق ومراجعة spam والوجهة قبل الإعلان عن النموذج.
