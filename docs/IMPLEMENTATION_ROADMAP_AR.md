# خارطة تنفيذ منصة INWP

## الغرض والحالة الحالية

هذه الخارطة تحول رؤية INWP إلى مراحل قابلة للمراجعة، وتفصل بين ما هو موجود في المستودع وما يحتاج إلى قرارات وتنفيذ. يحتوي المشروع حاليًا على نواة backend لمسار الحضور والمزامنة وبعض التصورات المعمارية، إضافة إلى بوابة عامة ثابتة. لا تُعد البوابة العامة لوحة إدارة، ولا تثبت الوثائق المعمارية أن ميزاتها منفذة أو جاهزة للإنتاج.

أُضيفت واجهة `site/console/` كعرض تفاعلي فقط. هي للشرح وتجربة التنقل، وتستخدم سجلات اصطناعية مضمّنة، ولا تملك تسجيل دخول أو قاعدة بيانات أو اتصالًا شبكيًا أو عمليات إدارية. لا تستخدمها لإدارة موظفين أو اتخاذ قرار رسمي.

## وحدات المنتج المستهدفة

- **الهوية والوصول:** موفر هوية مؤسسي معتمد، جلسات آمنة، تدوير رموز التجديد، RBAC وصلاحيات سياقية حسب الجهة والموقع، ومراجعة دورية للأدوار.
- **الهيكل التنظيمي:** جهات ووحدات ومواقع بعلاقات وتواريخ نفاذ ومصدر حقيقة واضح، دون افتراض أسماء أو هياكل حكومية غير معتمدة.
- **سجل الموظفين:** معرفات داخلية، حالة وظيفية، تعيينات وتغييرات مؤرخة، مع تقليل البيانات الشخصية إلى الحد الضروري.
- **الحضور والانصراف:** أحداث غير قابلة للاستبدال، سياسات وورديات معتمدة، استثناءات وتصحيحات مبررة، ومسارات مراجعة مفوضة.
- **الإجازات:** طلبات وموافقات وأرصدة تُحسب من قواعد رسمية معتمدة، وتُرفض التعديلات المتعارضة أو القديمة بوضوح.
- **الرواتب والاستحقاقات:** وحدة منفصلة لا تنفذ حسابات أو استقطاعات قبل اعتماد اللوائح والمعادلات ومصادر البيانات والاختبارات من الجهة المالكة.
- **العمل دون اتصال والمزامنة:** التقاط محلي محدود، طابور دائم ومشفّر حيث يلزم، مفتاح تكرار، إعادة محاولة متدرجة، كشف تعارضات ومصالحة صريحة دون استبدال صامت.
- **التدقيق والتقارير:** سجل إلحاقي مقاوم للتلاعب، وتقارير ذات نطاق تنظيمي وصلاحيات واضحة، مع منع تخزين المحتوى الحساس في cache عام.
- **الأجهزة والتكامل:** تعريف وثقة الأجهزة، مفاتيح وشهادات، عقود API وإصدارات مخطط متوافقة، ومراقبة لكل تكامل.

## مراحل التنفيذ وبوابات الاعتماد

### المرحلة صفر — أساس السلامة والأمن

إتمام المصادقة والتفويض قبل إتاحة أي سجل تشغيلي؛ ربط هوية الفاعل بسياق الجهة والموقع على الخادم؛ استكمال عزل المستأجرين في قاعدة البيانات باختبارات تحت دور غير مالك؛ ووضع الكتابات والتدقيق وoutbox ضمن معاملات ذرية. تتطلب التعديلات مفتاح idempotency وإصدارًا متوقعًا، وتعيد تعارضًا صريحًا بدل الكتابة فوق نسخة أحدث.

**بوابة الخروج:** اختبارات سلبية تثبت رفض الوصول غير المصرح، وعدم تسرب بيانات بين الجهات، وعدم تكرار الآثار عند إعادة الطلب، ورفض الإصدار القديم، وتسجيل الفشل والرفض بصورة قابلة للتتبع.

### المرحلة الأولى — الدليل والهيكل التنظيمي

تنفيذ الجهات والوحدات والمواقع وسجل الموظف والتعيينات المؤرخة ببيانات اصطناعية. يبقى مصدر الحقيقة وسياسة النقل وتعارض التعيينات قرارات حوكمة مطلوبة، ولا يُستخدم رقم وطني أو حقل حساس قبل اعتماد الحاجة والغرض والاحتفاظ.

### المرحلة الثانية — الحضور والإجازات

استكمال قوائم الحضور والاستثناءات، ومسار تصحيح أو اعتراض ذي صلاحية وتدقيق، ثم بناء الإجازات وربط الأرصدة بقواعد معتمدة. لا تُقبل الموافقات المتزامنة أو التعديلات بعد القرار بصمت.

### المرحلة الثالثة — العمل دون اتصال

تطبيق طابور محلي ومصالحة مع الخادم، وتحديد العمليات المسموح بها في الوضع المتدهور، واختبار الانقطاع وإعادة الإرسال وتعطل العامل وتعارض النسخ. لا يُفعّل التخزين المحلي للسجلات الحساسة قبل مراجعة التشفير والاحتفاظ وإمكانية المسح.

### المرحلة الرابعة — الرواتب والتقارير

تبدأ بعد اعتماد قواعد الاستحقاق والاستقطاعات والتقويمات ومصادر البيانات ومسار الفصل بين المهام. تُختبر الحسابات على حالات مصطنعة ومراجعة مستقلة قبل أي استخدام حقيقي.

### المرحلة الخامسة — التشغيل والإتاحة

بيئات تطوير واختبار وإنتاج منفصلة فعليًا، مفاتيح وشهادات وإدارة أسرار، نسخ احتياطي مشفر واستعادة مجرّبة، مراقبة وتنبيهات وخطة استجابة للحوادث واختبارات حمل وتعافٍ. لا يُعلن هدف إتاحة 99.95% قبل وجود بنية واتفاق تشغيل وقياسات تثبته.

## ضوابط غير قابلة للتجاوز

1. لا توجد بيانات إنتاج أو بيانات شخصية حقيقية في العرض العام أو الاختبارات أو عينات التطوير.
2. GitHub Pages يستضيف مواد عامة منقحة وعرضًا اصطناعيًا فقط؛ لا يستضيف API أو لوحة إدارة موثوقة أو أسرارًا.
3. كل قراءة وكتابة تشغيلية تحتاج هوية موثقة وتفويضًا سياقيًا على الخادم، وليس مجرد إخفاء عناصر في الواجهة.
4. الكتابات الحساسة تحفظ ضمن معاملات ACID، بتدقيق إلحاقي، وidempotency، وفحص إصدار، وتتعامل مع التعارضات صراحة.
5. تُفصل بيانات التطوير والاختبار عن الإنتاج؛ لا تُستخدم قاعدة مشتركة للاختبار الذي قد يعدل بيانات إنتاج.
6. تُرفض الميزات أو عمليات النشر التي لم تجتز اختبارات الأمن وسلامة البيانات والتعافي، ولا تُعامل هذه الخارطة أو واجهة العرض كاعتماد تشغيلي.

## قرارات مطلوبة قبل ربط بيانات حقيقية

تحتاج المرحلة التشغيلية إلى اعتماد موفر الهوية، ونموذج الجهة والوحدات والمواقع وصلاحياتها، وقواعد دورة حياة الموظف، ومصدر الحقيقة لكل كيان، وسياسات الإجازات والرواتب، وفترات الاحتفاظ، ومستوى الخدمة وخطة التعافي، وبيئة الاستضافة وقاعدة البيانات المنفصلة لكل مرحلة. تبقى هذه النقاط مفتوحة بدل ملئها بافتراضات برمجية.
