# وحدات منصة INWP — نطاق التنفيذ المقترح

## الحالة بوضوح

أُضيف إلى `site/console/#platform` معرض استكشافي لمفاهيم الوحدات، يعمل محليًا ببيانات مصطنعة. الأزرار والحسابات في هذا المعرض محاكاة مؤقتة داخل المتصفح فقط؛ لا توجد API أو قاعدة بيانات أو مصادقة أو قرارات أو تخزين محلي. لا يعني ظهور بطاقة أن الخدمة الخلفية منفذة أو معتمدة.

توجد خدمة API أولية مستقلة للقراءة والتحديث المحدود لحالة الموظف، لكنها لا تقدم الوحدات أدناه. قاعدة البيانات الحالية لا تتضمن جداول أعمال لهذه الخدمات ولا سياسات RLS أو منح تشغيل مكتملة. لذلك لا تُربط أي وحدة بموظفين حقيقيين حتى استيفاء بوابة المرحلة صفر في خارطة التنفيذ.

## مبادئ تصميم مشتركة

- فصل الخدمة العامة والعرض الاصطناعي عن API وقواعد البيانات التشغيلية؛ لا أسرار ولا بيانات أفراد في GitHub Pages.
- لكل مورد مجال واضح، مالك بيانات، تصنيف، غرض معالجة، سياسة احتفاظ، مصدر حقيقة، ونطاق تفويض.
- كل انتقال حالة محدد بقائمة سماح؛ كل كتابة ذرية في PostgreSQL مع فحص إصدار متوقع ومفتاح idempotency وتدقيق إلحاقي ضمن المعاملة نفسها. لا استبدال صامت للتعارضات.
- تحقق الصلاحيات على الخادم وفق الدور والسياق التنظيمي لكل إجراء ومورد، مع RLS كطبقة دفاع إضافية بعد اختبارات بدور runtime غير مالك.
- وضع حد أدنى للبيانات؛ لا حقل حر أو مرفق في قنوات عامة أو غير مصنفة. سجلات التدقيق تحفظ بيانات وصفية مسموحة فقط، ولا تنسخ نصوص التذاكر أو الأسرار.
- المعلومات المجمعة لا تُنشر إلا بعد مراجعة خطر إعادة التعرف، وحد أدنى لحجم المجموعة، وقواعد كبت الخلايا الصغيرة ومنع استنتاج الأفراد من المقارنات المتكررة.
- لا تتخذ خوارزمية أو مساعد قرارًا في التوظيف أو الترقية أو الأهلية أو الاستحقاق. أي دعم قرار مستقبلي يتطلب سياسة معتمدة ومراجعة بشرية وأثرًا تدقيقيًا.

## نطاق الوحدات

### الخدمات والتواصل

1. **مركز المعاملات:** فهرس لحالات الخدمات المصرح للمستخدم برؤيتها، متطلباتها، نواقصها، مالك الخطوة، والمدة المستهدفة. يجب أن يتبع كل نوع معاملة آلة حالات واعتمادًا رسميًا، ولا يمنح المركز نفسه صلاحية اعتماد.
2. **التعاميم والسياسات:** نشر محتوى معتمد متعدد اللغات ومؤرخ، مع سجل نسخ وجمهور مخول وإثبات اطلاع عند الحاجة. لا تُعد معاينة الاطلاع موافقة قانونية.
3. **تذاكر الدعم:** تصنيف وتوجيه ومهلة استجابة وسجل حالة. يحدد مالك العمل حقول النص والمرفقات والاحتفاظ والإخفاء؛ وصول فريق الدعم محدود ولا يمنح حق قراءة سجل HR.
4. **الاقتراحات:** قنوات مصنفة مع خيار إخفاء الهوية حيث تسمح الحوكمة، ومكافحة إساءة الاستخدام ومسار فرز ومتابعة؛ لا تُجمع بيانات شخصية غير لازمة.
5. **الدليل الإجرائي:** محتوى ثابت معتمد ومؤرخ مرتبط بمصدره. المساعد المحتمل يجيب من هذه المواد فقط، ويصرح عند عدم المعرفة ويحوّل المستخدم إلى الجهة المختصة؛ لا يستنتج سياسة أو قرارًا.
6. **مركز التنبيهات:** صندوق إشعارات داخلي قابل للضبط حسب تفضيل المستخدم، مع عدم كشف محتوى حساس على شاشة قفل أو قناة غير موثوقة.

### الموظفون والتطوير

7. **التفويض المؤقت:** نطاق إجراء وموارد محددة، تاريخ بدء وانتهاء، موافقون مستقلون، منع التفويض الذاتي وتضارب المهام، سحب فوري، وانتهاء تلقائي. لا يرث المفوض نطاقًا أوسع من المفوض.
8. **التقويم الإداري:** أحداث ومواعيد مملوكة للجهة مع جمهور ونطاق ووقت مصدر؛ المواعيد النظامية لا تُنشر إلا من مصدر رسمي وتظل قابلة للتدقيق.
9. **المهارات والتدريب:** كتالوج دورة وتسجيل وإنجاز ومصدر تحقق للمهارة، مع موافقة على رؤية بيانات الملف وتحديد من يثبتها وكيفية تصحيحها.
10. **الفرص الداخلية:** فرص معلنة بمعايير وشروط واضحة ومسار تقديم ومراجعة بشرية موثق. لا ترتيب خوارزمي للأفراد أو توصية آلية بالقبول.
11. **نقل المعرفة والتسليم:** قائمة مهام ووثائق مرتبطة بمدة ونطاق، بتصنيف وصول وتاريخ انتهاء؛ لا تتحول الملاحظات إلى ملف تقييم موظف.
12. **تهيئة الموظف الجديد:** قائمة إرشاد عامة حسب الدور والجهة، وتُربط بحساب حقيقي فقط بعد إقرار IAM وسياسات الموظفين.

### التخطيط والضمان

13. **محاكي تخطيط القوى العاملة:** سيناريوهات مجمعة قابلة لإعادة الإنتاج مع الافتراضات والإصدارات ومصدر البيانات. النتائج دعم تخطيطي فقط، وليست توقعًا حتميًا أو قرارًا عن فرد.
14. **جودة البيانات:** قواعد معلنة للنقص والتكرار والتعارض، نتائج قابلة للتتبع، تصحيح بمسار اعتماد وتحقق إصدار، ومنع أي تعديل تلقائي صامت.
15. **استمرارية العمل:** خطط للمهام الحرجة والبدلاء والاستعادة بصلاحيات سرية، اختبارات وتمارين دورية وسجل مراجعة. تُحجب بيانات الأفراد ونقاط الاتصال عن البوابة العامة.
16. **مراجعة الخصوصية وطلبات البيانات:** مسار داخلي محكوم للتحقق من الهوية والحق والصلاحية، تقييم أثر الطلب، موافقات لازمة، استجابة محدودة، واحتفاظ موثق؛ يحتاج سياسة قانونية معتمدة قبل إتاحته.

### الرؤى والتكامل

17. **لوحة المؤشرات المجمعة:** مؤشرات مجمعة فقط افتراضيًا، حسب الغرض والنطاق، مع حد أدنى للمجموعات ومنع التنقيح إلى صفوف أفراد.
18. **كتالوج التكاملات:** سجل لعقد API وإصدارات المخطط والمالك والشهادة وسياسة إعادة المحاولة والحدود؛ يبدأ باختبارات اصطناعية، ولا يُوصل نظام حي قبل اتفاق مصدر الحقيقة وmTLS وتدوير الأسرار ومنع التكرار والمصالحة.
19. **بوابة البيانات العامة:** مجموعة منشورات معتمدة ومراجعة إفصاح، بتاريخ وتفسير ومصدر ومنهجية؛ البيانات الفردية والمجموعات الصغيرة لا تُنشر.
20. **لوحة قابلة للتخصيص:** تفضيلات عرض غير حساسة مرتبطة بحساب موثوق، لا تغيّر الصلاحيات ولا تتجاوز ضوابط النطاق.

## مراحل التنفيذ المقترحة

- **أ — إغلاق أساس السلامة:** موفر هوية وBFF للجلسة الآمنة وتدوير الاعتماديات، منح قاعدة بيانات أقل صلاحية، RLS واختبارات عزل، تحديد سياق موثوق لكل معاملة، تحديد بيانات واحتفاظ، حدود المعدل، تدقيق خارجي مقاوم للتلاعب، نسخ واستعادة، ومراجعة أمن مستقلة. لا تبدأ عمليات كتابة تشغيلية قبل اجتيازها.
- **ب — محتوى عام وقراءة مجمعة:** تعاميم وتقويم عام ومؤشرات مُراجعة جودة وبيانات عامة اصطناعية أو معتمدة، منفصلة عن سجل الموظف وبضوابط كبت المجموعات الصغيرة.
- **ج — خدمات غير تقريرية:** معاملات وتذاكر واقتراحات ودليل إجرائي وإشعارات، بعد تعريف صلاحيات النطاق والسرية والاحتفاظ وآلات الحالات والتدقيق.
- **د — التطوير المهني والصلاحيات المؤقتة:** تدريب ومهارات وفرص وتسليم وتفويض وتهيئة، بعد اعتماد سياسة الرؤية والموافقة وتعارض المهام والإنهاء والتصحيح.
- **هـ — التخطيط والتكامل والاستمرارية:** بعد اعتماد مصادر البيانات ومراجعة الخصوصية واختبارات الاعتمادية والتعافي؛ تبقى الأدوات دعمًا للبشر ولا تتخذ قرارات موظفين.

لا يعلن هدف توافر أو جاهزية وطنية حتى تتوفر بيئة تشغيل معتمدة وقياسات واتفاق دعم واختبارات تعافٍ تثبت ذلك. المبادئ السريرية الخاصة بالعينات والنتائج لا تنطبق على سجل القوى العاملة؛ تُطبق مبادئ السلامة العامة وسلامة البيانات والتدقيق وفق طبيعة المجال.
